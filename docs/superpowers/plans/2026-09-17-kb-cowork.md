# kb in Cowork Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the existing `kb` plugin usable in Claude Cowork by replacing PR #14's localhost-bridge machinery with surface-aware skills plus a documented per-project remote connector.

**Architecture:** One `kb` plugin serves both CLI and Cowork. In Cowork the Brain is a remote custom connector (Entra OAuth) named `brain`; the `connect` and `mode` skills gain Cowork-aware guidance; the bridge/installer/plist/ZIP tree from PR #14 is deleted. No local runtime, cross-platform by construction.

**Tech Stack:** Markdown SKILL files, JSON manifests, Python `unittest` (stdlib) for structure/content tests.

**Spec:** `docs/superpowers/specs/2026-09-17-kb-cowork-design.md`

## Global Constraints

- Plugin name stays `kb` verbatim — never rename it.
- Cowork connector naming convention: the connector MUST be named `brain` so its tools resolve as `mcp__brain__*`.
- Preferred connector auth is **Entra OAuth**; `X-API-Key` is the documented fallback.
- Tests run with `python3 -m unittest discover` from `bundles/kb/tests` (no `pytest`, no `python`; use `python3`).
- Do not add an `mcpServers` block to `bundles/kb/.claude-plugin/plugin.json` — `kb` ships no MCP server of its own (asserted by `test_plugin_json_exists_and_names_kb`).
- Keep existing `not_modeled` / citation discipline in answer skills unchanged.
- Preserve the existing `connect` contract tokens (`health`, `mcp-config`, `brain`) and `mode` contract tokens (`state.json`, `ambient`, `on`, `off`, `status`) — the CLI branches must still contain them.
- Commit after each task. Branch: `feat/generic-brain-cowork-plugin` (already checked out).

```markdown
# Using kb in Claude Cowork

`kb` is the same plugin in Claude Code (CLI) and in Claude Cowork (Desktop).
Cowork keeps its own plugin install state — installing kb in the CLI does not
make it appear in Cowork — so install it in Cowork explicitly, then point it at
your project's Brain via a remote connector. Nothing runs on your machine; the
connector runs in Anthropic's cloud, so setup is identical on macOS, Windows,
and Linux.

## 1. Install the kb plugin

1. Open **Customize → Plugins → Add marketplace** and enter the GitHub URL of
   the `applied-ai` marketplace (`onetest-ai/applied_skills`).
2. Install **kb** from that marketplace and enable it.

(Air-gapped alternative: upload a plugin ZIP of `bundles/kb` under
**Customize → Plugins → Add**, ≤50 MB.)

## 2. Add your project's Brain as a connector

Each project has its own Brain endpoint. Add it once per project:

1. **Customize → Connectors → Add custom connector.**
2. Paste your project's **HTTPS MCP URL** (Streamable HTTP transport).
3. Authorize with **Entra OAuth** (Advanced settings → OAuth client id/secret).
   If your endpoint uses a static key, set an `X-API-Key` header instead.
4. **Name the connector `brain`.** kb's skills call `mcp__brain__*`, so the
   name must be `brain` for them to resolve.
5. Enable the connector.

**In two projects?** Keep one connector per project and enable only the one
named `brain` for the current Cowork task — kb grounds itself in the active
`brain` connector.

## 3. Verify

Run `/kb:connect`. It calls `health` and reports whether the Brain is
reachable. Then use `/kb:ask`, `/kb:explore`, `/kb:challenge`, `/kb:brief`,
`/kb:report`.

## What differs from the CLI

- **Ambient mode (`/kb:mode`)** relies on a hook that does not fire in Cowork.
  In Cowork, ground answers by invoking the kb skills explicitly.
- **The SessionStart health line** reads a local store and is CLI-only.
```
